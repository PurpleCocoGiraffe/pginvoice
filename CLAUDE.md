## Architecture

This is a single-page React app (Vite, no router) with **one shell and many independently-stateful modules** (listed below; an earlier "four"/"ten" count went stale, so no number here). `src/Shell.jsx` mounts every module the user can open simultaneously and switches between them via CSS `display` (never conditional rendering / unmount), specifically so each module's in-memory state (an uploaded CSV, open filters, etc.) survives tab switching. Shell.jsx is also the real auth/session/RBAC/nav gate: it runs `LoginGate` against Supabase Auth, forces a password change for newly-created accounts (`must_change_password`), and builds the nav and the set of mounted modules from the user's module access (below). **Nav filtering is cosmetic only — real enforcement is Postgres RLS.** Mobile gets a different nav shape entirely (bottom tab bar + "More" sheet) instead of the sidebar.

Roles: `super_admin`, `admin` (admin tier: every module, overrides never apply, can't be locked out), `consultant`/`coordinator` (client-scoped; their clients are auto-derived from their ClickUp identity).

- **Module access is per user** (`20261016_user_permissions.sql`, `20261017_scoped_modules.sql`): scope `none`/`own`/`assigned`/`all` = override in `pginvoice_user_module_access` ?? role row in `pginvoice_role_presets` ?? `none` (`pginvoice_module_scopes` = grantable pairs). Consultant/coordinator preset: Overview + Invoicing `assigned`, Timesheets + Wages `own`, Clients/Accruals/Reporting `none`; everything else is admin tier only.
- Shell.jsx loads it via `pginvoice_my_access()` (refetched on focus; also returns `clickupUserNames`, the user's exact ClickUp spellings, `[]` for admins) and derives nav, mounting, the redirect guard and each module's scope prop (`moduleScopeProps`: null = everything, else `{ personId, userNames, clients }`) with the pure `src/permissions.js` (roles in `src/roles.js`, pinned by `permissions.test.js`). `resolveAccess`: RPC not deployed -> role-derived access; other error -> admins still role-derived, non-admins keep previous access or get a reload screen. Mobile bottom bar: the preferred four (unchanged for admins), then spare slots from the user's other visible modules.
- **Scoped modules: compute over full inputs, filter at display.** A scoped user's numbers must equal what an admin sees for the same card, so full inputs are loaded (SECURITY DEFINER RPCs where RLS would hide them) and only the *list* is narrowed; never compute from RLS-trimmed inputs (accruals, carry and roll-ups would silently change). A missing scoped RPC renders an honest "not available yet"; admins never use these paths.
- Client Invoicing's manual name-match overrides are shared in `pginvoice_name_matches` (`src/nameMatchesSync.js`; read with Invoicing access, admin-tier writes, optimistic + rolled back on error); an admin browser's legacy `pg-name-map-v1` localStorage map is moved up once (never overriding a row) and then cleared.
- **Deploy order for permission changes: migration, then `manage-users`, then frontend.**
- **Time entries are own + own clients** for non-admins (`20261022_entries_own_clients.sql`): a row is readable if its `user_name` is one of the user's ClickUp spellings or its folder maps (`pginvoice_folder_clients`) to one of their clients (directory rules, sub-projects included). The map is written by an admin's live Client Invoicing load from the pipeline's own cards (`folderAccess.js` `folderClientPairsAllMonths`: each card's `searchFolders` -> `profileClient`, every month, task-prefix synthetic folders also map their source folder; `folderAccessSync.js` adds missing pairs, never deletes). Scoped Invoicing also loads `pginvoice_clickup_months()` as `clickup.coveredMonths`, so a month with no visible rows still counts as covered (`billableMinutesByFolder`) -- without it the prior-month estimate differed by a whole package. Verified on live data: 404/404 client-months identical. SQL check: `supabase-tests/entries_own_clients_check.sql`. The policy is its own file, `20261023_entries_policy.sql`, applied only after the frontend is live and an admin Invoicing load has filled the map.

Shell.jsx is the **single owner** of `nameMatch.js`'s cost-centre singleton (`setDynamicCostCentres`; every module mounts at once and the matching is synchronous, so no page fetches or sets it): admins and users without Invoicing get `pginvoice_cost_centres` (`fetchCostCentres`); a non-admin with Invoicing gets `pginvoice_client_directory()`, fetched once there, its cost centres applied *before* the parsed directory is passed to Client Invoicing as `directory` (the task-prefix split runs when App fetches entries). Shell refreshes on `PG_COST_CENTRES_KEY` and passes Clients.jsx `costCentres` (`{ version, error, refresh }`); Clients calls `refresh()` after its own edits rather than fetching.

### Data flow: ClickUp → Supabase → frontend

Time-tracking data can arrive two ways, and downstream modules are written to not care which:

1. **Manual CSV upload** (legacy path, still supported) — parsed client-side with `papaparse`/`xlsx` (`parsers.js`).
2. **Live sync** — `supabase-functions/clickup-sync/index.ts` is a Deno Edge Function, run on a `pg_cron` schedule (not called by the browser directly, except for the manual "Sync now" button), that pulls entries from the ClickUp API and upserts them into `public.pginvoice_clickup_entries`. It processes one calendar month at a time (fetch → upsert → stale-row cleanup → discard) rather than accumulating everything in memory first — an earlier all-at-once version hit the Edge Function's compute limit on real historical data. `CLICKUP_API_TOKEN` is an Edge Function secret, never sent to the client.

`src/clickupSync.js` (browser-side) reads `pginvoice_clickup_entries` back out via `supabase-js` and reshapes it into **exactly the same row shape** `App.jsx` already produces from a CSV (`folder`, `task`, `minutes`, `billable`, `user`, `isInternal`, `monthKey`, `monthLabel`, `dateKey`) — so `CapacityDashboard`, `PerformanceScorecard`, and `TimesheetSummary` need zero changes regardless of data source. If you touch this row shape, update it in both `clickupSync.js` (frontend read) and `clickup-sync/index.ts` (Edge Function write) together.

The "internal vs billable folder" classification (`isInternalFolder` in `src/nameMatch.js`) is duplicated between the frontend and `clickup-sync/index.ts` (Edge Function/Deno) because the two can't share an import across runtimes — keep them in sync manually if the rule changes. Separately, rows carry `nonClientSpace` (from `space_id`, `isNonClientSpace` in `nameMatch.js`): time logged outside the two client spaces ("Clients", "PG CLIENTS") -- BDM's CRM, PG Tower, etc. -- is forced `isInternal` and also hidden from Client Invoicing's "excluded as internal" list, while Timesheets/Performance totals still count it. An unknown space (null `space_id`) is treated as a client space. It's a substring match against `["onboarding","induction","offboarding","handover","wip"]`; "Purple Giraffe" itself is explicitly **not** internal — it's the literal ClickUp login an external contractor (DMA) logs time under, and counts as billable like anyone else.

`src/dateMath.js`'s `adelaideLocalMidnightUtcMs` is a deliberately-duplicated twin (again, can't share code across the Deno/browser runtime split) of month-boundary math used by `clickup-sync`. It self-corrects via a re-measuring loop to handle Adelaide's DST transition (UTC+9:30/+10:30) correctly — an earlier off-by-one-day bug in this exact math broke sync once already, and it's regression-tested in `capacityData.test.js`. `dateMath.js` also holds browser-only Adelaide month helpers (`adelaideMonthKey`, `adelaideDayOfMonth`, `monthOffsetFor`, `wagesReviewMonthKey`) used by Wages review's month picker and ClickUp re-sync.

### The client/folder matching engine (`src/nameMatch.js`)

Central and heavily load-bearing across Client Invoicing, Capacity Planning, and Client Accruals — most of the codebase's documented bug history traces back to this file.

- `findMatch(name, candidates)`: exact match (confidence 1) → substring match (0.85) → token-Jaccard similarity (threshold 0.5). A name that normalizes to an **empty string** (e.g. ClickUp's literal "(No folder)" placeholder) must return `null` immediately — otherwise the substring branch treats `""` as a substring of everything and misattributes hours to an arbitrary candidate.
- `tokens()` strips a small stopword set (`and, the, co, pty, ltd, inc, group, of`) *unless* doing so would leave zero tokens, specifically so "Wills and Co" doesn't fuzzy-match "Toto and Co" on shared stopwords alone.
- `MULTI_FOLDER_CLIENTS`: hardcoded, prefix-based rules for clients whose real work spans several sibling ClickUp folders instead of one umbrella folder (Aus3C's training programs, Clarke Energy's sub-brands, Magain's ~20 per-agent folders, etc.). Each rule can carry `excludeFromAccrual` for sibling folders that are real client work (should roll up into total-hours views) but are billed separately from the retainer and must **not** count toward package-accrual math (e.g. Majestic Plumbing's "Quoted Web Project", Apex Communications' two quoted projects (Apex Comms is a separate client from Apex Energy), Warrina Homes' Employee Guide project). BAMSS Childcare Security Services is the inverse case: a separately-registered client whose hours nonetheless count toward Brisbane Alarm Monitoring's *same* shared package.
  - `multiFolderMatchesFor` (includes excluded sub-projects — "how much did we actually work") vs. `multiFolderAccrualMatchesFor` (drops them — package/accrual math specifically). A dynamic client's own registered `clickup_folder` is never itself a cost-centre row, so callers pass it as `multiFolderAccrualMatchesFor`'s optional third `ownFolder` argument (recomputeAccruals does; App.jsx folds it in itself) — without it, a client with a real cost-centre sibling accrued only the sibling's hours (Majestic Plumbing regression).
- **Dynamic cost centres** (`pginvoice_cost_centres`, fed in via `setDynamicCostCentres` from Shell.jsx/Clients.jsx): a client with explicit dynamic rows is managed *entirely* through the Clients module UI — any hardcoded `MULTI_FOLDER_CLIENTS` rule for that same client is ignored outright rather than the two silently merging.
- **Task-prefix cost centres** (`pginvoice_cost_centres` rows with `kind: 'task_prefix'`, `source_folder`/`task_prefix` columns): some clients (Aus3C first) moved from tracking each cost centre as its own separate ClickUp folder to logging everything into ONE shared folder, with the cost centre identified by a prefix on the *task name* instead ("IRAP - ...", "Cyber Meets - ...", with an unrecognized/"Corporate -" prefix falling through to the parent). `splitTaskPrefixFolders(rows)` rewrites a matching row's `folder` to a synthetic identity that reuses the exact string the old separate-folder convention already used (e.g. "Aus3C IRAP") — so a month straddling old-and-new tracking, or a client using both conventions at once, unifies under one identity automatically, and every downstream consumer (roll-ups, accrual math, Capacity Planning matching) needs zero changes since it's all still keyed on `row.folder`. Applied once at both row-shape intake points (`clickupSync.js`'s live fetch and `parsers.js`'s CSV parser) — never in the edge function or the raw `pginvoice_clickup_entries` table, which stays a faithful mirror of ClickUp. Configured per client in the Clients module drawer's "Task-prefix cost centres" section.
- `CLIENT_TYPE_LABELS` / `TYPE_LABELS_SHORT` / `CLIENT_TYPE_TONES`: the canonical 7-type vocabulary (`package`, `hourly`, `quoted`, `map`, `project`, `strategy`, `ad_hoc`) plus a legacy `queensland` type. `CHART_TYPE_TONES` is a deliberately separate jewel-tone palette from `CLIENT_TYPE_TONES` because the badge palette reuses hues (package/strategy both use `--accent`), fine for a single badge but unreadable across 8 simultaneous chart lines.
- `basisToClientType` / `dominantClientType`: map Capacity Planning's 7-way "basis" vocabulary onto the client-type vocabulary; a multi-row "Combined" group is bucketed by whichever **fixed**-basis sub-row has the most agreed hours (actual hours can't be split back across sub-rows once matched to one folder).

### Client lifecycle and accrual math

- `src/clientsSync.js` manages `pginvoice_clients` plus a full scheduled-event system. Each client has an immutable `base_type`/`base_agreed_hours` snapshot and a mutable current `type`/`agreed_hours`, changed only via dated events in `pginvoice_client_events` (`type`, `consultant`, `offboarding`, `reactivation`, `hold`, `resume`). `applyDueClientEvents()` applies anything due, then **recomputes each affected client's current state from its full applied-event history**, picking each field's chronologically-latest event independently — this fixes a real production bug where a backdated correction event, added later but dated earlier than an already-applied one, used to lose on insertion order and silently revert a newer transition. `typeTimelineFor`/`typeForMonth`/`statusForMonth` replay this history to answer "what was this client's type/status as of month X," since a package's hours can change mid-year. Every mutation also writes to `pginvoice_client_history` (best-effort) for a unified audit trail. `updateQuotedAmount` is a direct field edit (not an event) — deliberately distinct from Package/Strategy transitions, which must stay replayable.
- `src/accrualsSync.js` bridges `pginvoice_accruals` into the same row shape the manual-upload parser produces. **`rowsToClients()`'s client-level `agreedHpm` field is a stale, last-write-wins scalar and must never be used for month-specific display** — only each row's own `months[mk].agreedHpm` is authoritative. Using the stale scalar caused three real regressions (ARAS stuck showing an old package figure after going off-package; Amorim Cork stuck at 0 after an hours increase; Warrina Homes stuck at an old value after an hours decrease) and is now explicitly regression-tested. `recomputeAccruals()` chains `newBalance = worked - agreed + prior`, replaying every non-override month from each client's earliest month on file forward — because a retroactive ClickUp edit to an already-closed month changes every later month's balance too. A human-set `is_override` cell is a frozen baseline, never recalculated; "on hold" pauses the accrual clock without zeroing the balance; a genuine off-package gap resets `prior` to 0. An offboarded/archived client accrues nothing inside its end periods (`endPeriodsFor`): a dated applied `offboarding` ends it from the first month whose 1st is on/after the effective date (2026-07-31 and 2026-08-15 both still accrue their whole month), a `reactivation` ends the period with its own month accruing in full and `prior` restarting at 0 (so an on-hold balance is dropped by offboarding), a reactivation with no preceding offboarding implies an undated end, and a client set offboarded/archived directly ends from `endDate` if set, otherwise after its last evidence month (worked hours > 0, override, or reset, within the window since any prior reactivation) — ended months clear existing computed rows ("Client offboarded"/"Client archived") and leave override rows untouched -- **except wrap-up drawdown**: while the balance carried into an ended month is owed (< 0, e.g. Warrina's -13.41 Aug reset), any month with worked hours writes a row (`WRAP_UP_NOTE`, agreed null) of `prior + worked` -- we owe the client its unutilised hours, so post-offboarding work is deducted from them; months with no work write nothing and hold the balance; once the balance reaches >= 0 the drawdown stops (an over-serviced client at offboarding is never drawn down). Leaving an ended stretch restarts `prior` at 0 (or the last ended month's `reset_value`). **Macro-sheet reset (Aug 2026 re-baseline):** `pginvoice_accruals.reset_value` (+ `reset_note`, `reset_at`; a check constraint limits it to `month_key = '2026-08'`) holds the legacy Excel macro sheet's authoritative closing accrual, same sign as `accrual_value`, and 0 is a real value (always `??`/`!= null`, never truthiness). A month's **carry-out** is `reset_value ?? accrual_value` (`carryOutOf` in `format.js`) — used as the next month's prior in every `recomputeAccruals` branch (package, override, on hold, off package), as `buildReconciliationClients().balances` (so Client Invoicing's Carry/estimate/mismatch/last-month export all pick it up; `computedBalances`/`resets` expose the parts), and in Overview's accrual health/trend. The computed `accrual_value` for the reset month is still recalculated and displayed unchanged; the reset shows as a data-driven "Remaining Reset" column (Remaining convention, i.e. `-reset_value`) only for a month that has any. `recomputeAccruals` never writes `reset_value` (upsert payloads list columns explicitly — keep it that way) but every rebuilt in-memory cell must carry `resetValue` over. The per-client replay loop is the pure `replayClientAccruals()`, directly tested. Strategy is treated identically to Package everywhere accrual math applies (`isPackageLikeType` in `format.js`); Quoted never accrues monthly — it's a single lifetime budget instead (`quotedAmount` minus lifetime worked hours).
- **Client Invoicing type rules (`reconcile.js`):** Quoted and MAP are lifetime hour budgets (`lifetimeBudgetFor`/`isLifetimeBudgetType`) -- budget minus billable hours from the engagement's start month, never monthly, never accrued; a base-type MAP starts at the profile `start_date`. `digital` (Digital Package) is fixed price: no package/carry/remaining, status `fixed_price`, never seeded, never accrued. `pginvoice_clients.fixed_fee` (AUD, display-only, `updateFixedFee`) prices a quote with no hours (AWIWA, $10,000): Client Invoicing shows the fee and its effective rate (fee / lifetime billable hours since the fee's own quote event). A month inside an offboarded client's end period with an owed carry-in (< 0) is a wrap-up drawdown (`endedCarryIn` + `wrapUpPrior`), mirroring `replayClientAccruals`. Per-cost-centre invoice caps live in `invoiceSplit.js` (`INVOICE_CAP_RULES`: Clarke Energy (CEA) $190/h, max $10,000 per invoice, split by `splitInvoice`). Sub-project rows are never package-like (`subProjectType`) and never a capGroup primary (`computePrimaryNameByGroup` in `clientListFilter.js`) -- choosing one hid both the parent and the child (ARAS / Majestic Plumbing regression); list search also matches each row's ClickUp folders (`searchFolders`).
- `src/usersSync.js` is a thin wrapper over the `manage-users` Edge Function (all real user CRUD needs the service-role key). `fetchOwnAccess()` calls `pginvoice_my_access()` (throws the raw error so Shell can detect "not deployed"); `setUserAccess()` calls `set_access`. `fetchClickupUserNames()` is paginated at 1000 rows (PostgREST's per-request cap) — unpaginated, it silently hid names past the first page in a 49k+ row table.

### Wages review data (`pginvoice_wage_*`, `pginvoice_leave_entries`)

Schema in `supabase-migrations/20261012_wages_review.sql`. Every table is RLS **admin tier only** (`pg_is_admin_tier()`) — payroll-adjacent data must never go into `pginvoice_app_state`.

- `pginvoice_wage_people` (pk = cap_people id; `include`, exact `clickup_user_names`, `xero_name`, `start_date`/`end_date`), `pginvoice_wage_rules` (effective-dated; basis `ft` / `pt_pattern` / `casual_xero` / `casual_pattern` / `casual_target`; a rule runs until the next one's `effective_from`, so a mid-month change splits the month), `pginvoice_wage_settings` (single row id=1), `pginvoice_wage_months` (`draft`/`closed` + `snapshot`), `pginvoice_wage_lines` (per month × person: `xero_hours` — null means not entered, never 0 — overrides, comments).
- **PG vs client classification** (`classifyClickup`): CLIENT = space is Clients (90167546842) or PG CLIENTS (54751434) AND folder not in `settings.pg_folders` AND (not `isInternalFolder`, or a client's own onboarding/offboarding folder per `isClientOnboardingFolder`: the folder name minus the onboarding words matches a registered client (`pginvoice_clients`) or a client-space folder that month, and no staff name -- staff onboarding, WIP and handover stay PG) AND the entry has a task; everything else (PG folders, internal folders, PG HQ/BDM/other spaces, task-less "Private" time) is PG. A row with a task but no `space_id` (synced before the column existed) uses `isNonClientSpace(null, null, folder)` (BDM folder names are PG, anything else client) and is warned about, including in the close-month checklist. ClickUp users map to people only by exact (case-insensitive) name; a name claimed twice is a conflict and counted for nobody.
- **Closed months**: closing waits for in-flight line saves, reloads every source fresh (all essential sources must load) and stores a snapshot of that (computed lines minus photo/other display-only bulk + settings + standard hours + holidays). A closed month always renders from that snapshot, never a recompute (later ClickUp edits / rule changes must not move signed-off numbers); comments (and the roster photo) stay live and are merged over it, and the banner lists which of ClickUp H / leave N, O, P, untyped / Q have since changed live. A DB trigger refuses changes to `xero_hours`/`ph_override_h`/`expected_override_h` and any INSERT on a closed month, so `upsertLine` updates first and inserts only when no row exists, and `closeMonth` creates a line row for everyone before closing. Reopening requires a reason and clears the snapshot.
- **Typed leave**: `pginvoice_leave_entries` (annual / personal / lwop / unspecified), edited in Consultants, which also rolls the total back into `cap_leaves` — only once `cap_leaves` has loaded, re-reading it right before each write and changing just that one person+month key (writing a stale/placeholder copy back once wiped every other total). Capacity Planning's leave cell is read-only and Capacity never writes `cap_leaves` (no save-effect). Wages review uses typed entries; a person with none but a legacy `cap_leaves` total gets it as untyped (warned), never dropped.
- `pginvoice_clickup_month_summary(p_month)` RPC (grouped by user × folder × space × billable × taskless) is paginated past the 1000-row cap. Cron only refreshes the current and previous month; older months get a "Re-sync ClickUp for this month" button (`clickup-sync` with `monthOffset`).

### Capacity data (`src/capacityData.js`, `src/capacityStore.js`)

- `pginvoice_app_state` is **admin tier only** (read and write, `20261022_capacity_admin_only.sql`). Non-admins get their own roster record (no rate/note) and own `cap_leaves` keys from `pginvoice_my_roster()` (`loadMyRoster` in capacityStore.js -- Overview `assigned`, Timesheets/Wages `own`, scoped Invoicing), and scoped Invoicing gets `cap_clients` from `pginvoice_client_directory().capClients` (pipeline fields only; `agreed` as its dense rank within the group, which `dominantClientType` treats identically -- pinned by `capClientsRanks.test.js`). A grantable module that reads the table directly (Clients, Accruals, Reporting at `assigned`) shows an empty roster for non-admins. SQL check: `supabase-tests/capacity_admin_only_check.sql` (shares `_permissions_setup.sql` with `scoped_modules_check.sql`).
- `capacityStore.js` wraps a single Supabase table `pginvoice_app_state` (jsonb value per key) — this replaced what used to be localStorage, so roster/client edits are visible across browsers/devices. `loadState` must **never** swallow a real query error and fall back to the seed default — doing so once let a transient network/RLS failure look identical to "first run, nothing saved yet," and the caller's save-effect then wrote the seed straight back over real data, destroying it. Only a genuine "no row" (`data === null`, no error) falls back quietly.
- `capacityData.js` is the shared library (used by App.jsx, CapacityDashboard, PerformanceScorecard, TeamDashboard, TimesheetSummary). `MONTHS` is generated dynamically (Dec 2025 through "now + 3 months"), never hardcoded to an end date. Real named public holidays (SA/WA/QLD) live in `src/publicHolidays.js`, covering 2025-06 through 2027-12 (`HOLIDAY_COVERAGE_END`; the 2027 dates must be re-verified against the state gazettes); capacityData re-exports `PUBLIC_HOLIDAYS`. Note `publicHolidayDays` (capacity) falls back to SA for an unknown state, while `holidaysFor` (wages) deliberately returns no holidays instead. `agreedAt(client, monthKey)` replays a client's ascending `{from, agreed}` history array and defensively skips malformed entries — a bad manual SQL edit putting `null`/non-object into this array once crashed the whole dashboard with no error boundary; the tradeoff chosen is "render this one client's hours slightly wrong rather than blank the entire page for everyone." `SEED_CLIENTS`/`SEED_PEOPLE`/`SEED_SUPPORT` are deliberately **empty**: they used to hold the real roster (rate targets, HR notes) and client list (offboarding reasons) and shipped in the public JS bundle; never put real data back in them. "Reset to sample data" was removed with them.

### Supabase access pattern

The live RLS policies and `pg_*` helpers (`pg_is_admin_tier`, `pg_has_client_access`) are recorded, not runnable, in `supabase-migrations/00000000_live_rls_record.sql` (the original RBAC migration was never checked in); re-export with `supabase-tests/export_live_rls.sql` before writing new policies. `pginvoice_profiles.person_id` (unique when set) links an account to its `cap_people` / wage person. Helpers `pg_module_scope(module)` / `pginvoice_my_access()`; the three permission tables are read-only to `authenticated`. Browsers can't insert/delete `pginvoice_profiles`, and may update only their own row's `must_change_password` true -> false (trigger `pginvoice_profiles_browser_write_guard`; ForcePasswordChange); everything else goes through `manage-users`. `supabase-tests/user_permissions_check.sql` validates the migration against a scratch Postgres (stub auth/profiles, applied twice, rolled back) -- never run it against the live project. `supabase-tests/scoped_modules_check.sql` does the same for `20261017_scoped_modules.sql` (directory completeness + redaction, accruals write lockdown, own-wage RPCs, `clickupUserNames` via `pg_my_clickup_user_names()` and its `lower(trim(user_name))` index). Scoped-module RPCs are SECURITY DEFINER with `search_path = public, pg_temp`, revoked from public/anon: `pginvoice_client_directory()` (refuses unless Invoicing is non-`none`; Overview uses RLS), `pginvoice_my_wage_months()` / `pginvoice_my_wage_line(p_month)` (Wages `own` + linked person; closed months only, own line, no comments or Xero map). `manage-users` requires a linked person only for explicit `own` overrides (presets are `own` too, and an unlinked user just sees a "no person linked" message).

`src/supabaseClient.js` uses the anon/publishable key only, which grants nothing on its own — every `pginvoice_*` table's RLS requires the `authenticated` role, not `anon`; real access comes from the signed-in session's JWT that `supabase-js` attaches automatically. All writes beyond what RLS allows a normal authenticated user go through an Edge Function using its own service-role key, which never reaches the client:

- `clickup-sync` — the scheduled ClickUp pull (see above). Callable only by the pg_cron jobs (`x-cron-secret` header, read by the cron commands from Vault `pginvoice_cron_secret` and checked by the service-role-only `pginvoice_cron_secret_ok()` RPC -- the secret exists only in Vault; see `supabase-migrations/20261022_cron_sync_secret.sql`) or a signed-in admin-tier user. `monthOffset` is capped at 60.
- `manage-users` — the only thing that can create/edit/delete `auth.users` rows. Re-derives the caller's own role server-side from `pginvoice_profiles` rather than trusting the request body. `resolveClickupClients` auto-derives which clients a new Consultant/Coordinator gets access to by looking up every ClickUp folder that person has ever logged time against (paginated past the 1000-row cap — some people have 6800+ entries) and exact-matching against `pginvoice_clients.clickup_folder` / `pginvoice_cost_centres.folder` (no fuzzy `nameMatch.js` logic ported into Deno; an admin can tick a client manually for edge cases). `syncClickupClientsForUser` only replaces `source='clickup'` rows — `source='manual'` and `source='capacity_lead'` rows are separately owned and never touched by the wrong path. `list`/`create` carry `personId` + `moduleOverrides` (`list` also the presets and grantable `moduleScopes`, and degrades if the migration is missing); `set_access` (`personId`, `moduleChanges` `{key: scope|null}`) refuses self-edits and admin-tier targets, needs a linked unclaimed roster person for any `own` scope, audit-logs what changed (also on a partial failure) and doesn't force a sign-out; promoting someone to admin tier clears their overrides and `person_id`. `reset_password` (`userId`, `password`; UserDrawer's Account section) sets an admin-typed temporary password, sets `must_change_password` and ends their sessions; refused for yourself and for a Super Admin target unless the caller is one (pure `passwordResetDecision` in `_shared/authz.ts`, tested in `edgeAuthz.test.js`), and the password is never audit-logged. Sign-outs (reset, role change) go through the service-role-only `pginvoice_revoke_user_sessions(uuid)` RPC (`20261025_revoke_user_sessions.sql`): supabase-js `admin.auth.admin.signOut` takes the user's own JWT, not a user id, so the old `signOut(userId)` calls always failed silently. Deleting `auth.sessions` kills refresh tokens; an issued access token lives until it expires. Guards against removing the last Super Admin, self-role-editing, and self-deletion; every mutation is written to `pginvoice_audit_log`; a failed `create` rolls back the newly-created auth user rather than leaving a stranded account.
- `clickup-key` — lets a Super Admin rotate the ClickUp API token from Settings.jsx instead of visiting the Supabase dashboard. Validates the token live against ClickUp's `/team` endpoint before persisting; stores it in `pginvoice_secrets` (RLS-enabled, zero policies — reachable only via service role) and never returns the raw token to the client, only a masked preview. Both actions (`status` too) are Super Admin only, checked server-side. Needs real CORS headers.
- Edge Function caller checks: the platform's `verify_jwt` is NOT authorization -- the public anon key is itself a valid JWT. Every function must resolve the caller itself (`supabase-functions/_shared/caller.ts`) and decide with the pure `_shared/authz.ts` (`authorize`, tested in `src/edgeAuthz.test.js`) before reading secrets or writing anything. Deploy a function together with `_shared/`.

### Client-side storage

- `src/idbStore.js` — IndexedDB key-value store, used only for the two large datasets (parsed ClickUp export can be several MB / 18k+ rows) that would risk hitting localStorage's ~5-10MB quota. Writing a value dispatches a `pg-idb-updated` window event so other mounted modules can react live to data another module just saved, instead of only picking it up on their own next mount.
- Everything else (filters, name-match overrides, theme) uses `localStorage` directly.
- Cache isolation (`src/cacheOwner.js`): Shell.jsx records the cache's owner user id (`CACHE_OWNER_KEY`) and, before any module mounts, wipes the IndexedDB store and every `USER_DATA_LOCAL_KEYS` entry when a different (or unrecorded) user signs in, and on explicit sign-out; a failed wipe shows a reload screen rather than mounting over the previous user's data; the same user keeps their cache, and theme/sidebar prefs and supabase-js's `sb-*` auth keys are never touched -- add any new data-bearing localStorage key to `USER_DATA_LOCAL_KEYS`.
- `src/storageKeys.js` centralizes every localStorage/IndexedDB/cross-module-event key as a named constant specifically so a writer and reader can't silently mismatch on a raw string literal.

### Utility layers

- `src/parsers.js` — CSV/XLSX parsing (`parseAccruedWorkbook`, `parseClickupCsv`). Duplicate month columns in a real spreadsheet are deduped keeping the **rightmost** (latest-entered) one. `parseStartTextMonth` deliberately parses ClickUp's pre-localized "Start Text" string rather than the raw UTC epoch, because converting the epoch can misfile a near-midnight session into the wrong month across the UTC/ACST boundary. "Time Tracked" (ms) is authoritative over "Time Tracked Text" (display string), which is only a fallback for older export presets.
- `src/publicHolidays.js` — the one SA/WA/QLD public-holiday table (weekday dates only, `HOLIDAY_COVERAGE_END`), shared by Capacity Planning and Wages review. Wages review warns for a month past the coverage end rather than showing zero public holiday hours.
- `src/leaveSync.js` — typed leave entries CRUD (`pginvoice_leave_entries`, throws on error), `LEAVE_TYPES`, and pure helpers (`deriveLeaveRows`, `totalLeaveHours`, `leaveDayHours`: only 38 h/week full-timers convert days at 7.6 h; everyone else enters hours).
- `src/wagesFormat.js` — Wages review display formatting (`fmtH`, `fmtSigned`, `fmtPct`, `fmtDay`, `monthLabel`, `basisName`); null always renders as "—", never 0.
- `src/format.js` — shared formatting helpers. `isPackageLikeType` (package/strategy only) is intentionally named differently from Clients.jsx's own `hasAgreedHoursField` (package/strategy/quoted) so a future edit can't accidentally import one where the other belongs and silently change Quoted's behavior.
- `src/printTemplate.js` — builds the branded PDF export; pulls in `letterheadFooter.js` and `nordiqueFont.js` (raw base64 asset blobs — a letterhead image and the licensed "Nordique Pro" font, embedded because the font has no public CDN/Google Fonts distribution; comments explicitly warn never to substitute another font like Quicksand).
